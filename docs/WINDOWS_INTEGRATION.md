# Интеграция Screenshooter с контекстным меню Windows

Документ описывает фактическую реализацию в ветке `feature/shared-integration-settings`. Интеграция является вспомогательной функцией приложения; её дальнейшая разработка приостановлена до отдельного решения.

## Цель

Позволить открыть изображение из Проводника Windows непосредственно в Screenshooter. Поддерживаются PNG, JPG, JPEG и BMP. Обе реализации запускают собранный файл `D:\Screenshooter\Screenshooter.exe`, а не `main.py`.

## Два независимых пути интеграции

### 1. Классическое контекстное меню

Реализация: `screenshooter/context_menu.py`.

- Работает через пользовательские записи реестра в `HKCU\Software\Classes\SystemFileAssociations`.
- Отдельные регистрации создаются для `.png`, `.jpg`, `.jpeg`, `.bmp`.
- Пункт меню называется Screenshooter.
- Команда запуска: `"D:\Screenshooter\Screenshooter.exe" "%1"`.
- Значок берётся из EXE.
- Поддерживается Windows 10 и Windows 11.
- Включение и выключение выполняются отдельно от современной интеграции.

Безопасность:
- перед включением проверяются все целевые записи;
- существующие значения, не совпадающие с ожидаемыми, не перезаписываются;
- выключение удаляет только значения, совпадающие с теми, которыми владеет Screenshooter;
- неизвестные значения, подразделы и ключи не удаляются;
- диагностика реестра не изменяет его.

### 2. Современное контекстное меню Windows 11

Реализация находится в `windows_context_menu/`:

- `ContextMenuCommand.cpp` — нативный COM-компонент `IExplorerCommand`;
- `Package.appxmanifest` — декларация packaged COM extension и команды Проводника;
- `Build-SparsePackage.ps1` — локальная сборка DLL, ресурсов, sparse MSIX и внешнего payload;
- `Build-ModernMenuPackage.ps1` — сборка MSIX из подготовленного комплекта установщика;
- `Install-ModernMenu.ps1` — проверка, развёртывание внешнего payload и регистрация MSIX;
- `Uninstall-ModernMenu.ps1` — снятие регистрации пакета;
- `prepare_package_assets.py` — генерация визуальных ресурсов;
- `.github/workflows/windows-context-menu.yml` — CI-сборка и проверки.

Минимальная целевая среда — Windows 11 build 22000+, x64.

### Фиксированная схема каталогов

`D:\Screenshooter` является ExternalLocation sparse MSIX. Структура после установки:

```text
D:\Screenshooter\
  Screenshooter.exe
  ContextMenu\
    ScreenshooterContextMenu.dll
    Assets\
      Square150x150Logo.png
      Square44x44Logo.png
```

В самом MSIX находятся манифест и `Assets\StoreLogo.png`. EXE и COM DLL не дублируются внутри пакета. COM DLL и две картинки VisualElements располагаются во внешнем каталоге. DLL запускает фиксированный EXE приложения.

Установщик:
- требует Windows 11 build 22000+;
- проверяет подпись, Publisher, Package Identity, манифест и payload;
- требует явного подтверждения через `ShouldProcess`;
- делает резервные копии заменяемых управляемых файлов;
- развёртывает DLL и два PNG;
- регистрирует MSIX с ExternalLocation `D:\Screenshooter`;
- при ошибке пытается восстановить прежние файлы.

Удаление снимает регистрацию MSIX текущего пользователя. Оно намеренно не удаляет EXE, DLL, PNG и классическую регистрацию.

## Настройки и аудит при запуске

`screenshooter/settings.py` хранит независимые флаги намерения пользователя:

- `classic_menu_enabled`;
- `modern_menu_enabled`.

Они не являются доказательством фактической регистрации. `screenshooter/settings_dialog.py` предоставляет отдельные переключатели.

`screenshooter/integration_startup.py` выполняет read-only аудит только тех интеграций, которые пользователь ранее включил. Классическую интеграцию можно восстановить после отдельного подтверждения. Для современной интеграции приложение сообщает о проблеме и направляет к ручному установщику; автоматическая регистрация не выполняется.

Аудит современной интеграции проверяет версию Windows, пакет текущего пользователя, Publisher, архитектуру, Identity, пути COM DLL и VisualElements, CLSID/Verb и наличие файлов. Он не активирует COM-сервер и не доказывает, что пункт виден в интерактивном Проводнике.

## Достигнутые результаты

В исходниках и тестах реализованы:

- классическая регистрация для четырёх форматов;
- безопасная проверка конфликтов и удаление только принадлежащих приложению значений;
- нативный COM command для современного меню;
- sparse MSIX с ExternalLocation;
- фиксированная структура внешних файлов;
- отдельные настройки classic/modern;
- read-only аудит при старте и восстановление только после согласия;
- PowerShell-сценарии сборки, установки и удаления;
- автоматизированные проверки манифеста, синтаксиса PowerShell, сборки DLL, структуры пакета, preflight, установки, повторной установки и удаления.

## Что подтверждено, а что ещё нет

### Подтверждено ранее локальными тестами

Для предыдущего локального состояния ветки пользователь запускал:

- целевые тесты настроек и startup audit: 13 passed;
- полный набор `screenshooter/tests`: 250 passed.

Эти результаты относятся к тому состоянию кода и не являются повторным тестированием текущего последнего коммита.

### Не подтверждено

- успешное завершение полного GitHub Actions после последних изменений;
- успешная установка пакета на реальном пользовательском ПК;
- COM-активация в Explorer;
- фактическое отображение команды в современном контекстном меню;
- открытие всех поддерживаемых форматов из реального Проводника.

Последний известный CI run (#59, commit `bd5ea965`) завершился ошибкой на шаге `Create and trust ephemeral CI signing certificate`: операция импорта временного сертификата в хранилище доверенных сертификатов runner превысила timeout 3 минуты. Предыдущие шаги — манифест, синтаксис PowerShell, сборка DLL, генерация ресурсов и комплект установщика — завершились успешно. Шаги сборки/подписи MSIX и установки не выполнялись.

Это проблема CI-окружения на этапе подготовки сертификата; она не доказывает ни работоспособность, ни неработоспособность интеграции на пользовательской Windows 11.

## Статус и дальнейшее решение

Интеграция сохранена в рабочей ветке, но дальнейшая доработка и устранение CI-блокера приостановлены. При возвращении к задаче следующий этап — отдельно решить проблему доверенного сертификата в CI, затем проверить установку на целевой Windows 11 и вручную проверить Explorer/COM. До этого не считать современную интеграцию завершённой или готовой к выпуску.
