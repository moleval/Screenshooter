# Screenshooter

Screenshooter — Windows-приложение для захвата экрана и редактирования изображений: аннотации, вставленные изображения, размытие, обрезка, история Undo/Redo, экспорт и системный трей.

## Состояние разработки

Актуальная рабочая ветка на момент обновления документации: `feature/shared-integration-settings`.

Ветка содержит интеграцию контекстного меню Windows, общие настройки интеграции и изменения приложения, накопленные поверх `main`. Она **не слита в `main`**. Перед переносом локальных изменений с другого компьютера обязательно проверьте `git status` и текущую ветку: локальные незакоммиченные файлы не попадают в GitHub автоматически.

Современная интеграция Windows 11 разработана на уровне исходников и сценариев установки, но её CI-проверка пока не завершена успешно. Последний зафиксированный запуск остановился на импорте временного сертификата в хранилище доверенных сертификатов GitHub runner. Это не подтверждает работоспособность интеграции в интерактивном Проводнике.

## Быстрый старт разработки

Требуется Windows 10/11, Python и зависимости проекта.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
python -m pytest
python main.py
```

Если используете уже подготовленное виртуальное окружение, повторно создавать его не нужно.

Основной набор тестов находится в `screenshooter/tests/`; конфигурация pytest — в `pytest.ini`.

## Сборка EXE

```powershell
python build.py --no-increment
```

Команда пересобирает текущую версию без увеличения номера BUILD. Обычный `python build.py` увеличивает BUILD. Не запускайте его только ради проверки кода.

## Интеграция с Проводником Windows

- Классическое меню: Windows 10 и Windows 11, пользовательская регистрация для PNG/JPG/JPEG/BMP.
- Современное меню: Windows 11 build 22000+, packaged COM extension и sparse MSIX.
- Обе интеграции независимы и включаются пользователем отдельно.
- Проверка при старте read-only; восстановление возможно только после явного согласия.
- Фиксированный каталог интеграции: `D:\Screenshooter`.

Подробности, структура каталогов, установка, ограничения и фактический статус: [docs/WINDOWS_INTEGRATION.md](docs/WINDOWS_INTEGRATION.md).

Руководство по работе с Git на двух компьютерах: [docs/DEVELOPMENT_WORKFLOW.md](docs/DEVELOPMENT_WORKFLOW.md).

## Архитектура

- `main.py` — точка входа.
- `screenshooter/app.py` — главное окно и координация приложения.
- `screenshooter/view.py` — графическая сцена и взаимодействие.
- `screenshooter/controllers/` — специализированные контроллеры.
- `screenshooter/items/` — графические элементы.
- `screenshooter/history/` — команды Undo/Redo.
- `screenshooter/ui/` и `screenshooter/widgets/` — интерфейсные компоненты.
- `screenshooter/capture/` — захват экрана и окон.
- `screenshooter/tests/` — основной набор тестов.
- `windows_context_menu/` — исходники нативного расширения и скрипты MSIX.

## Принципы работы с репозиторием

1. Один компьютер — одна активная рабочая копия в данный момент. Не редактируйте одну и ту же ветку параллельно на двух компьютерах.
2. Перед началом работы: `git status --short`, затем `git fetch origin`.
3. Сначала сохраните свои изменения отдельным коммитом или резервной копией; не используйте `git reset --hard`, `git clean` и `git add .` без проверки.
4. После работы запускайте тесты и отправляйте коммиты в одну согласованную рабочую ветку.
5. На втором компьютере сначала получайте изменения через `git fetch`, затем переключайтесь/обновляйте рабочую ветку только после проверки локального состояния.
6. Не коммитьте виртуальные окружения, кэш, результаты сборки, локальные настройки и личные файлы.
