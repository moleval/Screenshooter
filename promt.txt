# Screenshooter — Актуальное техническое задание

## 1. Цель проекта

Разработать нативное десктопное приложение для Windows, позволяющее пользователю мгновенно захватывать экран (весь монитор, активное окно или выделенную область), аннотировать полученное изображение с помощью набора инструментов и экспортировать результат. Приложение должно быть быстрым, интуитивно понятным и визуально приятным, конкурируя с такими инструментами, как ShareX или Lightshot, но с акцентом на качественное встроенное редактирование.

## 2. Архитектура

**Язык и версии:**
- Python 3.10+
- PyQt5 (с включённым `Qt.AA_EnableHighDpiScaling` для поддержки 4K-мониторов)

**Графическое ядро:**
- `QGraphicsView` и `QGraphicsScene`. Все аннотации являются наследниками `QGraphicsItem`.

**Архитектурный паттерн:**
Модульный, с разделением ответственности (MVC-подобный):

- `app.py` — главное окно, координация, горячие клавиши, компоновка тулбаров через компоненты `EditorToolbarStrip`.
- `view.py` (`EditorView`) — обработка событий мыши/клавиатуры, управление сценой, делегирование сложной логики в контроллеры.
- `controllers/` — специализированные контроллеры:
  - `manipulation_controller.py` — перемещение элементов, курсоры, временный указатель;
  - `blur_controller.py` — управление зонами размытия (создание, перемещение, изменение размера, рендеринг);
  - `pasted_image_controller.py` — вставленные изображения (добавление, масштабирование, обрезка, ручки);
  - `crop_overlay_controller.py` — визуальные элементы режима обрезки (рамка, затемнение, маркеры, текст разрешения);
  - `crop_cursor_factory.py` — фабрика курсоров для режима обрезки;
  - `floating_widget_manager.py` — видимость и синхронизация плавающих виджетов;
  - `keyboard_manager.py` — обработка клавиатуры в редакторе;
  - `clipboard_controller.py` — внутренний буфер обмена;
  - `status_bar_manager.py` — управление статусной строкой.
- `image_edit_controller.py` — координация операций с фоновым изображением (обрезка, поворот). Размытие вынесено в `blur_controller.py`.
- `items/` — изолированные классы графических примитивов.
- `history/` — централизованное управление состоянием через `QUndoStack` и кастомные `QUndoCommand`, разбитые по подмодулям (`item_commands`, `background_commands`, `blur_commands`, `image_commands`, `composite_commands`).
- `ui/` — компоненты интерфейса верхней панели (тулбары, метрики, разделители).
- `widgets/` — плавающие виджеты редактора (зум, палитра, толщина, информационный виджет, панели режимов).
- `theme.py` — централизованный менеджер тем оформления (светлая, тёмная, системная) через QSS.
- `settings.py` — сохранение настроек через `QSettings` (тема, путь сохранения, поведение).
- `tray.py` — системный трей, сворачивание, контекстное меню.

**Сторонние библиотеки:**
- `keyboard` — глобальные хоткеи;
- `pywin32` — захват окон через WinAPI;
- `mss` / `pillow` — резервные/вспомогательные операции с изображениями.

## 3. Реализованный функционал

**Захват экрана:**
- Оверлей выбора монитора (`capture/screen_overlay.py`);
- Выделение области с координатами (`capture/region_overlay.py`);
- Захват клиентской области активного окна через WinAPI (`capture/window_capture.py`).

**Аннотации:**
- Текст (с фоном), `TextItem`;
- Фигуры: прямоугольник (`RectangleItem`), эллипс (`EllipseItem`), заливка (`FilledRectItem`), облако (`CloudItem`);
- Линии: прямая (`LineItem`), волнистая (`WavyLineItem`);
- Стрелки: прямая (`ArrowItem`), кривая Безье (`CurvedArrowItem`), размерная линия с текстом (`DimensionItem`).

**Работа с изображениями:**
- Вставка из файла, буфера обмена или перетаскиванием (`PastedImageItem`);
- Перемещение, масштабирование, обрезка, поворот вставленных изображений;
- Первая вставленная картинка становится подложкой, если подложки нет.

**Редактирование фона:**
- Обрезка (`crop`) с рамкой, маркерами и текстом разрешения;
- Поворот на 90° (`rotate`);
- Добавление зон размытия (`BlurRegionItem`) с перемещением и изменением размера;
- Размытие ограничено границами рамки зоны (без выхода за пределы).

**Управление:**
- Масштабирование (зум) с плавающим виджетом `ZoomWidget`;
- Отмена/повтор действий (Undo/Redo) через `QUndoStack`;
- Временное переключение на инструмент «Указатель» через ПКМ или Ctrl;
- Множественное выделение элементов;
- Полноэкранный режим по `F11` или `Ctrl+Enter` с корректным восстановлением предыдущего состояния окна.

**Справка:**
- Встроенная справка по инструментам и горячим клавишам.

**Интерфейс (реализованная архитектура тулбаров):**
- `EditorToolbarStrip` — плоская контейнерная композиция (`QWidget` + `QHBoxLayout`);
- `AnnotationToolbar` — 6 инструментов аннотаций (`QWidget` + `QToolButton`);
- `ImageToolbar` — 4 инструмента изображения (`QWidget` + `QToolButton`);
- `OptionsToolbar` — толщина + палитра (`QWidget` + `QVBoxLayout`);
- `ToolbarSeparator` — визуальный разделитель (два: между аннотациями и изображениями, между изображениями и растяжкой);
- `layout_metrics.py` — единая система геометрических параметров;
- `MainActionBar` — строка действий (Отменить, Повторить, Снимок, Очистить, В буфер, Вставить файл, Из буфера, Сохранить как, Сохранить);
- Минимальная ширина окна вычисляется динамически на основе `minimumSizeHint` панелей и фактических margins layout;
- Поддержка тем оформления через `theme.py` (светлая, тёмная, системная; системная тема в текущей реализации эквивалентна светлой).

## 4. Реализованные технические решения

**Независимость маркеров:**
Класс `CropHandles` использует флаг `ItemIgnoresTransformations`, благодаря чему маркеры изменения размера не искажаются и не меняют визуальный размер при зуме сцены.

**Сложный Undo/Redo:**
Команды `CropCommand` и `RotateCommand` умеют сохранять и восстанавливать состояние зон размытия (`blur_state`), что предотвращает потерю данных при глобальных изменениях холста.

**Гибридное размытие:**
Функция `blur_region` использует временный `QGraphicsScene` с `QGraphicsBlurEffect` для качественного гауссова размытия (либо OpenCV при наличии), которое затем «впекается» в исходный `QPixmap`. Размытие применяется строго в пределах заданного прямоугольника.

**Контекстные плавающие виджеты:**
Панели выбора режима, цвета и толщины появляются динамически в зависимости от выбранного инструмента или выделенного объекта. Позиционирование централизовано в `LayoutManager` с поддержкой немедленного обновления (`immediate=True`) для предотвращения мелькания.

**Модульная история:**
Команды истории разбиты по подмодулям и экспортируются через `history/__init__.py`.

**Централизованная тема:**
`ThemeManager` в `theme.py` хранит палитры для светлой и тёмной темы, генерирует QSS и применяет `QPalette`. Переключение темы сохраняется в настройках.

**Динамическая минимальная ширина окна:**
Метод `_update_window_minimum_width()` вычисляет минимальную ширину как максимум из `minimumSizeHint` `MainActionBar` и `EditorToolbarStrip` плюс фактические margins центрального layout. При смене темы или изменении содержимого панелей минимум пересчитывается. Окно не уменьшается автоматически, если новый минимум меньше текущего размера.

**Отрисовка `TextItem`:**
Устранено двойное применение отступов в `boundingRect()` и `paint()`, из-за которого возникали артефакты (урезанная рамка, шлейфы при перемещении). Фон рисуется точно по границам `boundingRect()`, при изменении геометрии вызывается `prepareGeometryChange()`.

**Проведённый UI-рефакторинг (Шаги 1–9):**
- Шаг 1 (Baseline) — зафиксировано исходное состояние;
- Шаг 2 (Metrics) — создан `ui/layout_metrics.py`;
- Шаг 3 (Components) — созданы `AnnotationToolbar`, `ImageToolbar`, `OptionsToolbar`, `ToolbarSeparator`;
- Шаг 4 (EditorToolbarStrip) — создана плоская контейнерная композиция;
- Шаг 5 (Единая геометрия) — выравнивание границ тулбаров и редактора;
- Шаг 6 (Content-driven sizing) — тулбары конвертированы в `QWidget` + `QToolButton`; ширина определяется содержимым; `ThicknessWidget` и `ColorPaletteWidget` используют `QSizePolicy` вместо `setFixedWidth`;
- Шаг 7 (Window Geometry + Theme) — динамическая минимальная ширина окна, интеграция тем, добавлен второй разделитель;
- Шаг 8 (Regression) — добавлены тесты геометрии (`test_ui_geometry.py`), диагностика (`diagnose_geometry.py`), статический анализ (`check_ui_consistency.py`), `REGRESSION_NOTES.md`;
- Шаг 9 (Cleanup) — удаление легаси (`top_toolbar`, `addToolBar`, устаревшие константы, legacy QSS, `prototype_toolbar_layout.py`).

## 6. Архитектурные долги

1. **Отсутствие единого механизма манипуляции для обычных аннотаций.** Зоны размытия (`BlurRegionItem`) и вставленные изображения (`PastedImageItem`) имеют собственную логику обработки маркеров и перемещения через `CropHandles`. Обычные аннотации (линии, фигуры, стрелки, текст) **не имеют** маркеров изменения размера и поворота.

2. **Фрагментация обработки мыши.** Логика `mousePressEvent/MoveEvent/ReleaseEvent` в `view.py` перегружена из-за необходимости проверять состояния для фона, размытия, вставленных картинок и обычных фигур одновременно.

## 7. Текущий этап — Интеграция маркеров для манипуляций с обычными аннотациями

**Цель:**  
Наделить графические примитивы (линии, стрелки, фигуры, текст) возможностью изменения размера через визуальные маркеры.

**Правила расстановки маркеров:**

- **Линии и прямые стрелки** (`LineItem`, `WavyLineItem`, `ArrowItem`) — **3 маркера**:
  - два крайних — растягивание/уменьшение длины, перемещение начала или конца;
  - средний — преобразование прямой в дугу/сплайн (для стрелки — в кривую Безье).

- **Кривая стрелка** (`CurvedArrowItem`) — **3 маркера**:
  - начальная и конечная точки — изменение положения;
  - средний — перемещение контрольной точки Безье (изменение изгиба).

- **Фигуры** (`RectangleItem`, `EllipseItem`, `FilledRectItem`, `CloudItem`) — **8 маркеров**:
  - четыре угловых — растягивание/уменьшение от противоположного угла;
  - четыре серединных — растягивание/уменьшение по горизонтали или вертикали.

- **Текст** (`TextItem`) — **4 угловых маркера**:
  - растягивание/уменьшение от противоположного угла.

- **Размерная линия** (`DimensionItem`) — **2 маркера**:
  - начальная и конечная точки привязки.

**Что не входит в этап:**
- Поворот элементов (отдельный будущий этап).
- Новые типы аннотаций.

### 7.1. Доработка классов аннотаций (`items/`)

Добавить в классы `RectangleItem`, `EllipseItem`, `FilledRectItem`, `CloudItem`,  
`LineItem`, `WavyLineItem`, `ArrowItem`, `CurvedArrowItem`, `DimensionItem`, `TextItem` методы:

- `show_handles()` — создание и отображение маркеров;
- `hide_handles()` — удаление маркеров;
- `update_handles()` — обновление позиций маркеров при изменении геометрии или перемещении.

Реализовать методы получения и установки геометрии для каждого типа элемента:

- для фигур — `get_geometry_rect()` / `set_geometry_rect()`;
- для линий и стрелок — оперирование точками `start` / `end` (+ `ctrl` для кривой);
- для текста — оперирование прямоугольником текстового поля;
- для размерной линии — точки привязки.

### 7.2. Доработка `EditorView` и `ManipulationController`

- **`mousePressEvent`:**  
  добавить проверку попадания курсора в маркеры выделенных аннотаций (аналогично проверкам для `pasted_images` и `blur_regions`).

- **`mouseMoveEvent`:**  
  реализовать пересчёт геометрии в зависимости от перетаскиваемого маркера:
  - угловые маркеры — изменение размера с сохранением пропорций или свободно;
  - серединные — изменение по одной оси;
  - средний маркер линии/стрелки — преобразование в дугу или перемещение контрольной точки.

- **`mouseReleaseEvent`:**  
  зафиксировать изменение и создать команду для Undo/Redo.

- **Синхронизация выделения:**  
  при изменении выделения или смене инструмента вызывать `show_handles()` для выделенных и `hide_handles()` для остальных.

### 7.3. Особенности и ограничения

- Маркеры используют `ItemIgnoresTransformations` (постоянный визуальный размер при зуме) — уже реализовано в `CropHandles`.
- Для линий и стрелок количество маркеров — **3**, не 2.
- Для кривой стрелки средний маркер управляет контрольной точкой Безье.
- Для фигур — **8 маркеров**.
- Для текста — **4 угловых маркера** (только изменение размера, редактирование текста не затрагивается).
- При множественном выделении маркеры **не отображаются**.
- Поворот **не входит** в этап.

## 8. Точные требования текущего этапа

| Требование | Описание |
|-----------|----------|
| Маркеры видимы при выделении | При выделении аннотации маркеры появляются автоматически |
| Маркеры скрываются при снятии выделения | При снятии выделения маркеры удаляются |
| Изменение размера работает | Перетаскивание маркеров изменяет геометрию элемента |
| Маркеры не масштабируются | `ItemIgnoresTransformations` обеспечивает постоянный визуальный размер |
| Линии/стрелки — 3 маркера | `LineItem`, `WavyLineItem`, `ArrowItem` — начало, конец, средний (для дуги) |
| Кривая стрелка — 3 маркера | `CurvedArrowItem` — начало, конец, контрольная точка |
| Фигуры — 8 маркеров | `RectangleItem`, `EllipseItem`, `FilledRectItem`, `CloudItem` — углы и середины |
| Текст — 4 маркера | `TextItem` — угловые маркеры для растягивания |
| Размерная линия — 2 маркера | `DimensionItem` — точки привязки |
| Undo/Redo работает | Изменение размера можно отменить и повторить |
| Множественное выделение | Маркеры не отображаются при множественном выделении |
| Совместимость с темами | Маркеры корректно отображаются в светлой и тёмной теме |

## 9. Ограничения и что НЕ менять

- **Не менять** существующую логику `CropHandles` (используется для зон размытия и вставленных изображений);
- **Не менять** существующую логику обрезки подложки и вставленных изображений;
- **Не менять** архитектуру тулбаров (`EditorToolbarStrip`, `AnnotationToolbar`, `ImageToolbar`, `OptionsToolbar`);
- **Не менять** `theme.py`, `settings.py`, `tray.py` без отдельной задачи;
- **Не добавлять** поворот (это следующий этап);
- **Не добавлять** новые типы аннотаций (это будущие задачи);
- **Не менять** публичный интерфейс `EditorView` без необходимости;
- **Использовать** существующие константы из `constants.py` и `layout_metrics.py`, не создавать новые файлы констант.

## 10. Критерии готовности

- [ ] Все типы аннотаций (включая `TextItem`) показывают маркеры при выделении;
- [ ] Перетаскивание маркеров корректно изменяет геометрию элемента;
- [ ] Для линий/стрелок используются 3 маркера (начало, конец, средний);
- [ ] Для `CurvedArrowItem` — 3 маркера (начало, конец, контрольная точка);
- [ ] Для фигур — 8 маркеров;
- [ ] Для текста — 4 угловых маркера;
- [ ] Для размерной линии — 2 маркера;
- [ ] Изменение размера можно отменить (`Ctrl+Z`) и повторить (`Ctrl+Y`);
- [ ] Маркеры имеют постоянный визуальный размер при любом зуме;
- [ ] При снятии выделения маркеры исчезают;
- [ ] При смене инструмента маркеры исчезают;
- [ ] В режиме обрезки и размытия маркеры аннотаций не отображаются;
- [ ] При множественном выделении маркеры не отображаются;
- [ ] Работает во всех темах (светлая, тёмная, системная);
- [ ] Существующие сценарии не сломаны (обрезка, размытие, вставка изображений, текст);
- [ ] Код соответствует существующей архитектуре (контроллеры, история, константы).
